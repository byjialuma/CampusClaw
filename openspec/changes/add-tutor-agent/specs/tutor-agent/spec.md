## Purpose

提供班级限定的解题助手智能体：教师以提示词定义助手角色、以技能定义解题引导方式，学生在多轮会话中就题目提问，助手结合已保存的提示词、已启用的技能与本班知识库检索结果生成回答，回答以 SSE 逐段推送并按会话持久化。

## ADDED Requirements

### Requirement: 助手每次回答必须同时使用提示词、技能与知识库检索结果

系统 MUST 按以下顺序处理学生的一次提问：先由服务端认证中间件确认登录身份并从 JWT claims 取得班级标识；然后从数据库加载本班助手当前保存的提示词；再读取本班助手当前启用的技能；随后以该班级标识为强制过滤条件检索本班知识库分片；最后将提示词、技能指令、会话历史、检索分片与问题组装为模型上下文，调用 Chat Completions 生成回答。提示词、技能与知识库检索三者 MUST 参与同一次回答的生成，缺任一可生成来源时系统 MUST 按「知识库无命中」规则处理。系统 MUST NOT 在上述任何步骤读取请求参数中的班级标识。

#### Scenario: 一次提问走完完整编排链路

- **WHEN** 已登录学生提交一道题目
- **THEN** 服务端依次完成身份确认、提示词加载、技能读取、本班检索与回答生成，回答内容体现提示词定义的角色与解题引导要求，且回答附带的引用来自本次检索结果

#### Scenario: 伪造班级参数不影响助手范围

- **WHEN** 学生在提问请求中附加或篡改 `class_id`、`classId` 等班级标识参数
- **THEN** 系统忽略这些参数，仍仅按登录会话中的班级执行检索与回答

#### Scenario: 未登录调用助手接口被拒绝

- **WHEN** 未携带有效 JWT access token 调用助手提问、提示词管理或技能开关接口
- **THEN** 系统返回 HTTP 401，不返回任何回答、消息或助手配置数据

### Requirement: 提示词由教师编写保存并从下一轮对话生效

系统 MUST 为每个班级助手提供提示词的保存与读取能力：教师为本班助手编写提示词并保存，系统持久化到数据库；从保存成功后的下一轮提问开始，助手 MUST 使用新提示词生成回答；正在生成中的当前轮次 MUST NOT 受保存操作影响。学生 MUST NOT 能够修改提示词：修改接口 MUST 仅对教师角色开放，学生调用 MUST 返回 HTTP 403。

#### Scenario: 教师保存提示词后下一轮生效

- **WHEN** 教师将本班助手提示词由 A 改为 B 并保存成功，随后学生再次提问
- **THEN** 该轮及之后的回答按提示词 B 生成，回答中体现的角色设定与提示词 B 一致

#### Scenario: 学生修改提示词被拒绝

- **WHEN** 学生调用提示词保存接口提交新的提示词内容
- **THEN** 系统返回 HTTP 403，提示词内容保持不变

### Requirement: 解题引导技能由教师开关并改变回答方式

系统 MUST 为每个班级助手内置「解题引导」技能并提供启用/停用开关：开启时，助手回答 MUST 给出解题思路与引导，MUST 引用本班材料的标题与位置，MUST NOT 直接给出该题的最终答案；停用后，同一问题的回答方式 MUST 与开启时有明显区别（不再受「不直接给最终答案」约束）。技能开关 MUST 仅对教师角色开放，学生调用 MUST 返回 HTTP 403，且前端 MUST NOT 为学生提供技能开关控件。

#### Scenario: 技能开启时回答给思路不给最终答案

- **WHEN** 解题引导开启，学生提交一道本班材料中有对应内容可循的题目
- **THEN** 回答包含解题思路引导与本班材料标题、位置的引用，且不直接给出该题最终答案

#### Scenario: 技能关闭后回答方式明显不同

- **WHEN** 教师停用解题引导后，学生就同一问题再次提问
- **THEN** 回答不再遵循「不直接给最终答案」约束，回答风格与开启时存在可观察的明显差异

#### Scenario: 学生开关技能被拒绝

- **WHEN** 学生调用技能启用/停用接口
- **THEN** 系统返回 HTTP 403，技能状态保持不变

### Requirement: 知识库检索提供可回溯依据且无命中时不编造出处

助手生成回答前 MUST 以本班为边界检索知识库：命中时，回答 MUST 标注出处；前端 MUST 将每条出处渲染为紧凑的小型可点击跳转卡片，卡片上 MUST 仅显示原始文件名，MUST NOT 显示分片文本内容、位置文案与相关度等其他信息（按文件类型的位置信息 PDF 页码 / Markdown 章节路径 / TXT 行号区间保留在卡片数据中，不展示在卡片上）；同一份材料的多个分片命中 MUST 合并，引用区中每份材料 MUST 只出现一张卡片；点击卡片后 MUST 打开对应材料并定位到首个命中分片的位置。无命中时，回答 MUST 明确说明「资料中未找到」，引用列表 MUST 为空数组，系统 MUST NOT 编造任何出处。出处信息 MUST 与知识库检索结果一致，可回溯到本班材料原文。

#### Scenario: 命中时以仅含文件名的小型跳转卡片标注出处

- **WHEN** 学生提问命中本班材料分片
- **THEN** 回答附带的每条引用都呈现为仅显示文件名的紧凑小型卡片、不展示位置文案与分片文本内容，点击可打开对应本班材料并定位到该位置，且对应材料属于本班

#### Scenario: 同一材料的多个分片只显示一张卡片

- **WHEN** 检索结果中同一份材料有多个分片命中
- **THEN** 引用区中该材料只出现一张卡片（按材料去重），卡片点击定位到该材料首个命中分片的位置

#### Scenario: 无命中时说明未找到且引用为空

- **WHEN** 学生提问在本班材料中没有任何达到召回条件的分片
- **THEN** 回答明确说明资料中未找到相关内容，引用列表为空数组，回答中不出现任何编造的文件名或位置

### Requirement: 学生可连续追问且回答按会话保存

系统 MUST 为学生提供多轮会话能力：同一会话内学生可连续追问，每轮提问时系统 MUST 将该会话的历史消息带入模型上下文，使回答能呼应此前对话；每轮的用户提问与助手回答（含引用列表、当时的提示词与技能状态）MUST 按会话持久化；会话 MUST 仅对其所属学生可见，他人 MUST 无法读取或写入。会话与消息的班级归属 MUST 只来自登录会话。

#### Scenario: 连续追问获得有上下文的回答

- **WHEN** 学生在同一会话中先问一道题，再以「第三步为什么这样」追问
- **THEN** 助手回答能够关联此前提问的题目内容，而非当作全新问题处理

#### Scenario: 刷新后可回看历史回答

- **WHEN** 学生重新进入助手页面或刷新页面
- **THEN** 其历史会话与每轮回答（含引用）仍可完整查看

#### Scenario: 学生只能访问自己的会话

- **WHEN** 学生 A1 尝试读取学生 A2（或其他班学生）的会话消息
- **THEN** 系统返回 HTTP 403 或 404，不返回任何他人会话内容

### Requirement: 回答以服务器推送事件逐段返回

助手提问接口 MUST 以 SSE（`text/event-stream`）流式返回回答：在生成开始前推送本次检索得到的引用列表事件，随后将回答文本按生成进度逐段推送，流结束时推送结束事件并持久化该轮完整回答。生成中途失败时，系统 MUST 推送错误事件并返回友好文案，不泄露内部服务地址。学生因刷新或退出中断连接时，系统 MUST 停止向前端推送，并按实际已生成的完整内容或失败状态处理持久化。

#### Scenario: 回答逐段流式呈现

- **WHEN** 学生提交提问且生成成功
- **THEN** 前端在回答生成过程中即能陆续收到多段文本并增量渲染，流结束后能看到完整回答与仅含文件名的引用跳转卡片

#### Scenario: 引用先于回答文本到达

- **WHEN** 流式回答开始
- **THEN** 引用列表事件先于回答文本事件到达前端，前端可先渲染仅含文件名的出处跳转卡片

#### Scenario: 流式生成失败推送友好错误

- **WHEN** 模型网关在流式生成过程中不可用或报错
- **THEN** 接口推送错误事件，前端展示「助手暂不可用」类友好文案，不泄露内部服务地址

### Requirement: 教师侧助手配置入口与学生侧不可见性

前端 MUST 为教师提供本班助手的提示词编辑与解题引导开关入口；学生视图 MUST NOT 出现上述控件，学生仅能看到提问入口与会话回答。前端控制点的缺失 MUST NOT 是唯一防线：提示词修改与技能开关 MUST 由服务端按角色强制校验。

#### Scenario: 学生视图无配置入口但服务端仍拦截

- **WHEN** 学生登录后使用助手页面，并尝试以任何方式调用提示词保存或技能开关接口
- **THEN** 页面不出现相应控件，直接调接口时服务端返回 HTTP 403
