## Why

现有知识问答是单轮、无引导的通用问答。课程需要一个面向学生的解题助手智能体：教师通过提示词定义助手是谁、通过技能（解题引导）定义怎么引导解题、知识库提供可回溯依据，三者必须同时参与每一次回答，且回答以流式方式逐段推送并按会话留存，支持学生连续追问。

## What Changes

- 新增解题助手智能体能力：学生就题目提问时，系统依次完成「确认身份与班级 → 加载教师保存的提示词 → 读取已启用的技能 → 检索本班知识库 → 生成回答」，同一次回答必须同时用上提示词、技能与知识库检索结果。
- 新增会话式多轮对话：学生可连续追问，历史消息随每次请求带入模型上下文；每轮回答（含引用）按会话持久化到 MySQL。
- 新增 SSE 流式返回：回答以服务器推送事件逐段返回前端，结束后持久化完整回答与引用。
- 新增提示词管理：教师为本班助手编写并保存提示词，从下一轮对话生效；学生不能修改（服务端角色校验）。
- 新增技能管理与「解题引导」：教师可开启/关闭本班助手的解题引导技能，学生不能开关；开启时回答必须给思路并引用本班材料的标题与位置、不直接给出最终答案；关闭后同一问题的回答方式明显不同。
- 知识库检索结果参与回答：命中则在回答中以紧凑小型跳转卡片标注出处（卡片仅显示文件名，不展示位置文案与片段等内容，点击跳转定位到材料原文）；无命中则明确说明资料中未找到，不编造出处；班级只从登录会话（JWT claims）读取。
- 登录、角色校验、上传入库、按班级检索沿用既有实现；本次不做独立检索页改造。
- 不做：作业提交、作业批改、错题讲解、异步队列、关怀式对话。

## Capabilities

### New Capabilities

- `tutor-agent`: 解题助手智能体——教师侧提示词与技能管理、学生侧多轮会话问答、RAG 检索参与生成、SSE 流式回答与会话持久化。

### Modified Capabilities

（无——登录、角色、上传、检索均沿用 `classroom-knowledge-base` 既有要求，不改变其行为；助手通过内部服务复用 Embedding 与向量检索，不新增独立检索页面。）

## Impact

- **数据库**：`assistants` 表新增系统提示词字段；`skills` 表新增启用状态字段；新增 `conversations`、`messages` 两张会话表（schema 与 Go 侧幂等建表同步）。
- **后端**（Go net/http）：新增 `internal/tutor` 编排服务（提示词/技能加载 → 历史组装 → 检索 → Prompt 构造 → 流式生成）；`internal/llm` 新增流式 Chat Completions 支持；`internal/server` 新增会话、消息、SSE 提问、提示词管理、技能开关路由；`internal/seed` 播种本班助手与解题引导技能。
- **前端**（React）：HomePage 新增助手视图——左侧会话/追问输入，右侧 SSE 逐段渲染回答与仅含文件名的紧凑引用跳转卡片；教师侧新增提示词编辑与解题引导开关（教师可见，学生不可见）。
- **部署**：`docker-compose.yml` 无新增容器；Nginx 需关闭 `/api/tutor` SSE 路径的响应缓冲（`X-Accel-Buffering`），否则流式分段会被代理缓冲成一次性返回。
- **外部依赖**：沿用 LLM 网关（Chat Completions 流式）与 Embedding 网关；API Key 仍仅服务端持有。
