## Why

解题助手当前是「一个班级一个助手、每轮把全部已启用技能同时并入 system 提示」的粗粒度模型：技能无法按问题命中单条，检索落空时又用固定文案结束，助手不能再按提示词作答；教师也无法在同一班级里维护多个面向不同场景的智能体、并各自绑定技能与材料。本次变更引入班级内多智能体与「一次提问至多命中一个技能」的词法路由，并把「检索落空」从固定文案改为仍按提示词作答。

## What Changes

- **新增班级内多智能体**：新增智能体实体（一个班级可维护多个智能体，每个智能体有自己的名称与提示词）；教师端「助手设置」标签升级为「智能体管理」。
- **技能与材料按智能体绑定**：新增绑定关系（技能 → 智能体、材料 → 智能体）。未绑定到某智能体的技能/材料 MUST NOT 参与该智能体的回答与召回。
- **单技能词法路由（BREAKING）**：一次提问至多命中一个技能。候选集 = 当前智能体绑定且已启用的技能；按技能「适用条件」关键词在问题文本上的命中数计分（lexical scoring），取最高分的一条；同分取技能编号较小者；零命中即不选技能。未绑定的技能即使适用条件命中也不参与路由。旧的「全部已启用技能逐条并入」语义被替换。
- **工具调用只随命中技能（BREAKING）**：只有本轮命中的技能才解析并调用其 MCP 工具；其余已启用技能不再调用、不写审计。
- **解题引导约束**：本轮命中技能的**名称包含「解题引导」**时，回答 MUST NOT 写出最终答案、选项、得数或完整解题过程；该约束由技能正文指令承载。
- **检索优先、落空仍作答（BREAKING）**：检索命中高于相似度下限的分片时，回答优先依据这些材料并用 `[n]` 标出出处；检索落空、或该智能体没有绑定材料时，不再返回固定文案，仍按该智能体的提示词作答，引用列表为空数组，回答中不出现编号，也不编造出处。
- **会话绑定智能体**：新建会话时固定所选智能体，该会话内后续提问沿用同一智能体。
- **学生侧智能体选择**：学生默认使用本班「教师最新设计」的智能体（按最近更新取），并可在左侧导航切换其他智能体。
- **存量迁移**：现有 `assistants` 记录逐个迁移为同班的默认智能体（沿用原名称与提示词）；存量技能全部绑定到该默认智能体；班级全部讲义也绑定到该默认智能体，保证迁移后行为不倒退。

## Capabilities

### New Capabilities
- `agent-management`: 班级内多智能体实体与其技能/材料绑定、会话绑定智能体、学生选择智能体与其默认规则、教师侧智能体管理入口。

### Modified Capabilities
- `tutor-agent`: 技能参与方式由「全部已启用逐条并入」改为「词法路由至多命中一条」；工具调用只随命中技能；命中名称含「解题引导」时的作答约束；检索改为优先且落空仍作答、以 `[n]` 标出出处；召回限定在该智能体绑定的材料内。
- `home-navigation`: 教师端「助手设置」标签升级为「智能体管理」；学生左侧导航展示本班智能体列表并默认选中最近更新的智能体。

## Impact

- **数据库**：新增 `agents`、`assistant_skills`、`assistant_materials` 表；`conversations` 增加智能体归属；`assistants` 迁移为默认智能体。
- **后端**：`backend/internal/tutor`（词法路由、system 组装、检索阈值、`[n]` 编号、工具阶段、落空作答）、`backend/internal/server`（智能体与绑定接口）、`backend/internal/db`（schema 与幂等迁移）。
- **前端**：`HomePage.tsx`（教师标签改名、学生侧智能体列表与默认选中）、`AssistantSettings.tsx` / `SkillManagement.tsx`（升级为智能体管理）、`TutorView.tsx`（`[n]` 出处渲染）。
- **接口**：新增教师侧智能体及其绑定管理接口、学生侧智能体选择与会话创建接口；现有助手/技能/会话接口语义随之调整。
- **兼容**：`internal/qa`（独立知识问答）的固定文案行为本次保持不变；`/api/search`、`/api/qa` 路由保留。
