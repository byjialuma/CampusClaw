## ADDED Requirements

### Requirement: 助手按会话智能体组装上下文并按单技能路由作答

系统 MUST 按以下顺序处理学生的一次提问：先由服务端认证中间件确认登录身份并从 JWT claims 取得班级标识；再按**会话绑定的智能体**加载其当前保存的提示词；随后读取该智能体**绑定且已启用**的技能作为候选技能集，并对其进行一次词法路由（至多命中一条技能）；再以该班级标识与**该智能体绑定的材料**为过滤条件检索本班知识库分片；最后将提示词、本轮命中的技能内容（若有）、会话历史、检索分片与问题组装为模型上下文，调用 Chat Completions 生成回答。提示词（为空时用内置兜底）与知识库检索 MUST 始终参与同一次回答的生成；技能参与方式 MUST 为「候选集内至多一条命中技能的内容并入」（本条取代此前「全部已启用技能逐条并入」的语义；候选集为空或零命中时，仅以提示词与检索生成，不算缺失来源）。检索 MUST 沿用知识问答的班级过滤与单次检索语义：每次提问独立检索一次本班分片，不做跨轮检索复用。系统 MUST NOT 在上述任何步骤读取请求参数中的班级标识；对非本班或非本人的资源访问，系统 MUST 表现得与「没有这条数据」一致（404），不暴露资源存在性。

#### Scenario: 一次提问走完完整编排链路

- **WHEN** 已登录学生提交一道题目
- **THEN** 服务端依次完成身份确认、按会话智能体加载提示词、读取候选技能并词法路由、限定绑定材料的本班单次检索与回答生成，回答内容体现提示词定义的角色与该轮命中技能的要求，且回答附带的引用来自本次检索结果

#### Scenario: 候选技能来自当前智能体的绑定

- **WHEN** 学生在其会话绑定的智能体下提问，本班另有一条已启用但未绑定到该智能体的技能其适用条件命中问题
- **THEN** 本轮候选技能集只含绑定到该智能体的技能，未绑定的技能不被命中，其内容不影响回答

#### Scenario: 伪造班级参数不影响助手范围

- **WHEN** 学生在提问请求中附加或篡改 `class_id`、`classId` 等班级标识参数
- **THEN** 系统忽略这些参数，仍仅按登录会话中的班级与会话绑定的智能体执行检索与回答

#### Scenario: 未登录调用助手接口被拒绝

- **WHEN** 未携带有效 JWT access token 调用助手提问、提示词管理或技能开关接口
- **THEN** 系统返回 HTTP 401，不返回任何回答、消息或助手配置数据

### Requirement: 一次提问按词法计分至多命中一条技能

系统 MUST 在候选技能集（当前智能体绑定且已启用的技能）内、仅依据技能正文的「适用条件」行做词法命中计分（lexical scoring）：计分口径为「问题文本中命中的适用条件关键词个数」，命中越多得分越高；每个候选技能 MUST 先按此口径得分，再取分数最高的一条作为本轮命中技能；分数相同时 MUST 取技能编号较小者；全部技能得分为零（零命中）时 MUST NOT 命中任何技能。候选集之外的技能（未绑定到当前智能体，或已停用）MUST NOT 参与路由，即其适用条件虽命中问题也不得被选中。未声明「适用条件」行的技能在本轮 MUST NOT 参与词法计分（视为零分，不构成命中）。路由结果 MUST 在回答生成前确定，且 MUST 在同一轮内保持稳定（同一问题、同一候选集与技能键值下 MUST 得到同一结果）。本轮命中的技能 MUST 通过 SSE meta 事件的技能列表暴露给前端；零命中时该列表 MUST 为空。

#### Scenario: 取最高分的一条技能

- **WHEN** 候选集中有两条技能，其适用条件关键词命中问题文本的个数分别为 2 与 1
- **THEN** 本轮命中命中个数为 2 的那条技能，另一条不参与本轮回答

#### Scenario: 同分取技能编号较小者

- **WHEN** 候选集中两条技能命中关键词个数相同，且其中一个技能编号较小
- **THEN** 本轮命中技能编号较小的那一条

#### Scenario: 零命中即不选技能

- **WHEN** 候选集中没有任何技能的适用条件关键词出现在问题文本中
- **THEN** 本轮不命中任何技能，meta 的技能列表为空，回答仅按提示词与检索生成

#### Scenario: 未绑定技能即使适用条件命中也不参与

- **WHEN** 一条已启用技能未绑定到当前智能体，但其适用条件关键词出现在问题文本中
- **THEN** 它不进入候选集，本轮不命中它，其工具不被调用

#### Scenario: 未声明适用条件的技能不参与命中

- **WHEN** 候选集中某技能正文没有「适用条件」行
- **THEN** 该技能在本轮得分为零，不因问题内容被命中

### Requirement: 命中名称含解题引导的技能时不给出最终答案

当本轮命中的技能**名称包含「解题引导」**时，回答 MUST NOT 写出该题的最终答案、选项、得数或完整解题过程，MUST 以解题思路与步骤引导为主，并 MUST 引用本班材料的标题与位置。该约束 MUST 由技能正文指令承载：命中技能的内容 MUST 并入本轮 system 提示，回答 MUST 遵循该内容中的指令。本轮命中的技能名称不含「解题引导」时，系统 MUST NOT 施加上述约束。约束生效与否 MUST 可由可观察的回答差异验证。

#### Scenario: 命中解题引导技能时不给出最终答案

- **WHEN** 本轮命中的技能名称包含「解题引导」，且其正文要求只给思路不给最终答案
- **THEN** 回答给出解题思路与步骤引导并引用本班材料标题、位置，不写出最终答案、选项、得数或完整解题过程

#### Scenario: 未命中解题引导技能时不受该约束

- **WHEN** 本轮未命中任何名称含「解题引导」的技能
- **THEN** 系统不施加「不给最终答案」约束，回答风格与命中时存在可观察差异

### Requirement: 召回按相似度下限过滤并以 [n] 标出处且落空仍按提示词作答

助手生成回答前 MUST 以本班为边界、并在该会话智能体绑定的材料范围内检索知识库，召回 MUST 以可配置的相似度下限（`SEARCH_MIN_SCORE`）过滤：低于下限的分片 MUST NOT 进入回答依据。有高于下限的命中时，回答 MUST 优先依据这些材料，并在回答文本中以 `[n]` 顺序编号标出出处（`n` 与引用列表序号一致，自 1 起递增）；前端 MUST 将每条出处渲染为紧凑的小型可点击跳转卡片，卡片上 MUST 仅显示原始文件名，MUST NOT 显示分片文本内容、位置文案与相关度等其他信息（按文件类型的位置信息 PDF 页码 / Markdown 章节路径 / TXT 行号区间保留在卡片数据中，不展示在卡片上）；同一份材料的多个分片命中 MUST 合并，引用区中每份材料 MUST 只出现一张卡片；点击卡片后 MUST 打开对应材料并定位到首个命中分片的位置。检索落空（无高于下限的命中）、或该智能体没有绑定任何材料时，系统 MUST NOT 再用「根据已有材料无法回答该问题」一类固定文案结束：回答 MUST 仍按该智能体的提示词生成，引用列表 MUST 为空数组，回答文本中 MUST NOT 出现任何 `[n]` 编号，且 MUST NOT 编造任何出处。出处信息 MUST 与知识库检索结果一致，可回溯到本班材料原文。

#### Scenario: 命中时以 [n] 标出处并以仅含文件名的卡片呈现

- **WHEN** 学生提问命中本班（且属于该智能体绑定材料）的分片
- **THEN** 回答文本以 `[n]` 顺序编号标出出处，每条引用呈现为仅显示文件名的紧凑小型卡片、不展示位置文案与分片文本内容，点击可打开对应本班材料并定位到该位置

#### Scenario: 低于相似度下限的分片不作为依据

- **WHEN** 检索返回的分片相似度均未超过相似度下限
- **THEN** 这些分片不出现在回答依据中，引用列表为空数组，回答文本中不出现任何 `[n]` 编号

#### Scenario: 同一材料的多个分片只显示一张卡片

- **WHEN** 检索结果中同一份材料有多个分片命中
- **THEN** 引用区中该材料只出现一张卡片（按材料去重），卡片点击定位到该材料首个命中分片的位置

#### Scenario: 检索落空仍按提示词作答且不编造出处

- **WHEN** 学生提问在本班（且属于该智能体绑定材料）中没有任何超过相似度下限的分片
- **THEN** 回答仍按该智能体的提示词生成（不出示固定文案），引用列表为空数组，回答文本中不出现编号，也不出现任何编造的文件名或位置

#### Scenario: 智能体未绑定材料时仍作答

- **WHEN** 该会话智能体未绑定任何材料，学生对其提问
- **THEN** 回答仍按该智能体的提示词生成，引用列表为空数组，回答文本中不出现编号，也不编造出处

### Requirement: 远端工具调用只随本轮命中的技能

学生提问时，系统 MUST 先完成词法路由，并仅为本轮**命中**的那一条技能处理其工具引用（零命中时 MUST NOT 解析或调用任何技能声明的 MCP 工具，MUST NOT 产生相应审计）。内置引用 `knowledge_search` 沿用既有本班检索（始终执行，行为不变）；MCP 引用则按其所属服务器缓存清单与令牌调用远端 `tools/call`。技能声明的「适用条件」行（值以逗号分隔的关键词）MUST 作为该技能在本轮路由中的命中计分依据；本轮命中的技能，其声明的 MCP 工具 MUST 被调用；本轮未命中而仍启用、仍绑定的技能，其声明的 MCP 工具 MUST NOT 被调用（本条取代此前「未声明适用条件即启用即调用」的语义）。同一轮内同一工具引用 MUST NOT 重复调用。远端调用的结果文本 MUST 作为数据拼入该轮用户消息的上下文，并 MUST 明确标注为工具返回的数据而非系统指令，MUST NOT 改写系统提示词；持久化的用户消息内容 MUST 仍为学生的原始问题。远端调用 MUST 受超时上限约束，超时或远端报错时 MUST 记为出错状态并继续生成回答，MUST NOT 使整轮回答失败。当引用的服务器未处于已连接状态、工具不在其缓存清单中、或该服务器在本班已不存在时，系统 MUST 记为拒绝状态，MUST NOT 发起远端调用，MUST NOT 静默当作成功。

#### Scenario: 命中技能即带令牌调用且回答体现工具结果

- **WHEN** 教师把含 `formula_hint@campus-tools` 引用的技能绑定到当前智能体并启用，学生就该技能可识别的主题提问并命中该技能
- **THEN** 服务端带令牌调用远端工具，回答内容体现工具返回的信息

#### Scenario: 未命中技能时不调用其工具

- **WHEN** 某已启用且已绑定的技能本轮未被路由命中，但其声明了 MCP 工具引用
- **THEN** 该工具不被调用，本轮工具调用列表中不含该引用，且不产生该引用的审计记录

#### Scenario: 调用结果作为数据注入而非系统指令

- **WHEN** 远端工具返回的文本中包含类似指令的语句
- **THEN** 该文本仅作为用户消息中的数据被送入模型，系统提示词与角色约束不受其影响

#### Scenario: 持久化的用户消息仍为原始问题

- **WHEN** 学生提问并触发了工具调用
- **THEN** 该会话中该轮用户消息的持久化内容仍是学生的原始问题

#### Scenario: 远端超时或报错仍生成回答

- **WHEN** 远端工具调用超时或返回错误
- **THEN** 该引用被记为出错状态，系统继续生成并返回回答，学生仍能收到回答

#### Scenario: 未连接服务器的工具调用记为拒绝

- **WHEN** 命中技能引用的服务器处于未连接状态，学生提问命中该技能
- **THEN** 该引用被记为拒绝状态，未发起远端调用，且不表现为成功

#### Scenario: 已删除服务器的工具调用记为拒绝且无审计行

- **WHEN** 命中技能引用的服务器在本班已被删除，学生提问命中该技能
- **THEN** 该引用在响应中记为拒绝状态，且不产生审计记录
