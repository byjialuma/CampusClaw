## Purpose

为校园教学材料知识库提供基于 JWT access token 的无状态认证机制：用户登录后获得签名 JWT，后续请求通过 `Authorization: Bearer` 请求头携带；服务端不维护会话状态，仅验证 token 签名与有效期；所有访问控制在服务端强制，班级边界与角色权限保持不变。

## MODIFIED Requirements

### Requirement: 账号密码登录

系统 MUST 提供登录页，教师与学生均使用账号（用户名）+ 密码登录。登录成功后，系统 MUST 生成一个签名 **JWT access token** 并在响应体中返回（包含 token 字符串与过期时间戳），MUST NOT 创建服务端会话，MUST NOT 向浏览器写入任何认证相关的 Cookie。密码 MUST NOT 以明文形式存储或校验。登录失败时 MUST 返回统一的认证失败提示，不得泄露「用户不存在」与「密码错误」的区别。

#### Scenario: 教师使用正确账号密码登录成功

- **WHEN** 教师在登录页输入正确的用户名与密码并提交
- **THEN** 系统返回 HTTP 200，响应体包含 JWT access token 与过期时间，前端将 token 存于本地存储，进入知识库主页面

#### Scenario: 使用错误密码登录被拒绝

- **WHEN** 用户输入存在的用户名与错误密码提交登录
- **THEN** 系统返回 401 与「用户名或密码错误」提示，不返回 token

#### Scenario: 用户名不存在时登录被拒绝

- **WHEN** 用户输入系统中不存在的用户名提交登录
- **THEN** 系统返回 401 与错误密码场景完全一致的失败提示，不泄露该用户名是否存在

### Requirement: 未认证访问必须被引导或拒绝

所有知识库页面与数据接口均为受保护资源。未携带有效 JWT access token 访问受保护**前端页面**时，系统 MUST 将浏览器引导至登录页；未携带有效 JWT access token 调用受保护 **API** 时，系统 MUST 返回 401，不得返回任何业务数据。

#### Scenario: 未登录直接访问受保护页面被引导到登录页

- **WHEN** 未登录用户在浏览器直接打开知识库主页面（或任意受保护前端路由）
- **THEN** 浏览器被重定向到登录页，且登录成功后可进入最初请求的页面

#### Scenario: 未登录调用受保护数据接口返回 401

- **WHEN** 请求未在 `Authorization` 头中携带有效 JWT access token 调用材料列表、内容或下载接口
- **THEN** 系统返回 HTTP 401，响应体不包含任何材料数据

### Requirement: 退出登录

系统 MUST 提供退出入口。退出后，前端 MUST 立即清除本地存储的 JWT access token，页面返回登录页；已退出的 token 若仍在有效期内且被再次携带访问受保护接口，系统 MUST 正常验证通过（JWT 无状态特性，不维护黑名单）。

#### Scenario: 用户点击退出后 token 被清除

- **WHEN** 已登录用户点击页面右上角的退出按钮
- **THEN** 前端清除本地存储的 JWT access token，页面返回登录页；后续请求因未携带 token 而返回 401

#### Scenario: 过期 token 被拒绝

- **WHEN** 用户携带已过期的 JWT access token 调用受保护接口
- **THEN** 系统返回 HTTP 401，前端检测到 401 后清除本地 token 并跳转至登录页

### Requirement: 学生调用上传接口必须被服务端拒绝

系统角色分为教师（teacher）与学生（student）。上传材料是教师专属能力：学生端 MUST 同样保留上传入口与上传接口路径，但任何已认证学生调用上传接口时，服务端 **MUST** 返回 HTTP 403 与中文错误信息「学生无权限上传文件」。访问控制 MUST 在服务端强制执行，不得以「前端隐藏按钮」作为唯一限制手段。

#### Scenario: 学生上传材料返回 403

- **WHEN** 已登录的学生通过页面上传入口（或直接构造请求）调用材料上传接口提交文件
- **THEN** 服务端返回 HTTP 403，响应包含「学生无权限上传文件」，且不产生任何材料记录或文件存储

#### Scenario: 学生绕过前端直接调用上传接口仍被拒绝

- **WHEN** 学生使用自己的有效 JWT access token，绕过页面直接向后端上传接口发起 multipart 请求
- **THEN** 服务端同样返回 403，不写入任何材料数据

### Requirement: 班级是服务端强制的数据边界

每个用户 MUST 唯一归属于一个班级，每份材料 MUST 唯一归属于一个班级。材料列表、内容查看与下载 MUST 在**服务端**按当前 JWT access token 中声明的 `class_id` 过滤：列表只返回本班材料；直接访问外班材料的内容或下载 MUST 被拒绝。不得依赖前端过滤或隐藏实现隔离。

#### Scenario: 材料列表只包含本班材料

- **WHEN** A 班成员请求材料列表
- **THEN** 返回结果只包含归属 A 班的材料，不包含 B 班或任何其他班级的材料

#### Scenario: A 班成员访问 B 班材料被拒绝

- **WHEN** A 班的已登录用户使用 B 班材料标识请求材料内容或下载接口
- **THEN** 系统返回 HTTP 403，不返回该材料的任何内容与元数据

#### Scenario: 修改请求参数无法越权访问外班材料

- **WHEN** 用户通过篡改材料标识、班级标识等请求参数尝试访问非本班材料
- **THEN** 服务端依据 JWT access token 中的班级归属判定，返回 403，越权访问不成立

### Requirement: 教师上传材料并写入知识库

教师可上传扩展名为 txt、md、pdf 的材料文件。系统 MUST 校验文件类型，对非法类型返回 400；接受的文件 MUST 将文件内容写入受控存储，并将一条材料记录写入数据库，记录名称 MUST 等于上传文件的原始文件名，并关联上传者所在班级与上传者身份。上传成功后，该记录 MUST 立即出现在本班材料列表中。

#### Scenario: 教师上传合法材料后本班列表可查

- **WHEN** 教师上传一个名为 `第一章讲义.txt` 的 txt 文件并收到成功响应
- **THEN** 数据库新增一条材料记录，名称为 `第一章讲义.txt`、归属教师所在班级，随后请求本班材料列表时能查到该记录

#### Scenario: 上传非允许类型文件被拒绝

- **WHEN** 教师上传扩展名为 docx（或 exe、png 等）的文件
- **THEN** 系统返回 HTTP 400 并说明仅允许 txt、md、pdf，且不产生材料记录与文件存储

#### Scenario: md 与 pdf 材料同样可入库

- **WHEN** 教师分别上传一个 md 文件与一个 pdf 文件
- **THEN** 两次上传均成功，两条记录均以原始文件名出现在本班材料列表中

### Requirement: 材料列表展示与文件内容预览

知识库主页面 MUST 以列表展示本班材料，列表项名称即材料上传时的原始文件名。用户点击列表项后，页面 MUST 在右侧区域展示该材料内容：txt 与 md 以文本形式展示（md 经过渲染），pdf 以内嵌方式展示。

#### Scenario: 点击材料在右侧查看内容

- **WHEN** 用户在左侧列表点击一条本班 txt 或 md 材料
- **THEN** 右侧区域展示该材料的文本内容，列表中显示的名称为上传时的原始文件名

#### Scenario: 点击 pdf 材料可预览

- **WHEN** 用户点击一条本班 pdf 材料
- **THEN** 右侧区域以内嵌方式展示该 pdf 的内容

### Requirement: 经鉴权的新页面文件下载

用户可对当前可见的本班材料发起下载，下载 MUST 在浏览器新页面（新标签页）中完成。下载页面 MUST 凭有效 JWT access token 向服务端请求文件；当 token 不存在或已失效时（包括在下载页面刷新后凭证无法认证的情况），下载页面 MUST 跳转至登录页，不得下载文件。

#### Scenario: 在新页面下载本班文件成功

- **WHEN** 已登录用户点击本班材料的下载按钮
- **THEN** 浏览器打开新页面，前端从本地存储取出 JWT access token 并在请求头中携带，服务端鉴权通过后以原始文件名返回文件内容，浏览器完成保存

#### Scenario: 下载页面刷新后无法认证身份则跳转登录页

- **WHEN** 用户在本地存储无有效 JWT access token 的状态下打开或刷新某材料的下载页面
- **THEN** 下载页面无法完成身份认证，自动跳转到登录页，且不发生文件下载

#### Scenario: 下载外班材料被拒绝

- **WHEN** A 班用户在新页面请求下载 B 班材料
- **THEN** 服务端返回 403，下载页面不获得文件内容

### Requirement: 六类核心数据结构与预置种子数据

系统 MUST 建立并持久化六类核心数据结构：**班级（class）、用户（user）、讲义（handout，即知识库材料）、作业（assignment）、助手（assistant）、技能（skill）**。全新初始化的数据库 MUST 包含预置数据：班级 A 与班级 B；教师 A（归属 A 班，角色为教师）；学生 A1（归属 A 班）与学生 B1（归属 B 班）；两班各有至少一条标题可明确区分班级归属的讲义材料；作业、助手、技能结构也 MUST 各写入种子记录。种子账号的用户名与初始密码 MUST 通过环境变量注入，不得在代码或镜像中硬编码密码。

#### Scenario: 全新启动后可使用预置账号登录并看到本班材料

- **WHEN** 使用 Docker Compose 全新启动系统，并使用预置的教师 A 账号登录
- **THEN** 登录成功，材料列表中出现 A 班预置讲义，且不出现 B 班预置讲义

#### Scenario: 预置学生账号体现班级边界

- **WHEN** 分别使用学生 A1 与学生 B1 账号登录并查看材料列表
- **THEN** A1 只能看到 A 班讲义，B1 只能看到 B 班讲义，两班讲义标题可明确区分

#### Scenario: 种子账号口令由环境变量控制

- **WHEN** 部署时通过环境变量设置种子账号密码后启动系统
- **THEN** 必须使用环境变量中设置的密码才能登录成功，代码与镜像中不存在写死的种子账号密码

### Requirement: Docker Compose 一键启动与健康检查

系统 MUST 通过 Docker Compose 编排 Nginx、Go 应用与 MySQL 8.0 三个服务并完成初始化（建表与种子数据）。请求链路 MUST 为：浏览器 → Nginx → Go → MySQL。应用 MUST 提供无需认证即可访问的 `GET /health`：当应用与数据库均正常时返回 HTTP 200；当依赖不可用时返回 5xx，不得返回 200。

#### Scenario: 一键启动后健康检查通过

- **WHEN** 在全新环境执行 `docker compose up` 并等待所有服务就绪后访问 `GET /health`
- **THEN** 返回 HTTP 200，且通过 Nginx 暴露的入口可以正常打开登录页

#### Scenario: 数据库不可用时健康检查失败

- **WHEN** Go 应用存活但无法连接 MySQL 时访问 `GET /health`
- **THEN** 返回 5xx 状态码，明确反映依赖不健康

### Requirement: 仅 Nginx 对外暴露

面向用户的唯一入口 MUST 是 Nginx。Go 后端服务与 MySQL 数据库 MUST 仅在 Compose 内部网络可达，其端口不得发布到宿主机或外部网络，用户无法绕过 Nginx 直接访问后端接口或数据库。

#### Scenario: 外部无法直连后端与数据库端口

- **WHEN** 系统启动后，从宿主机或外部网络尝试直接连接 Go 应用端口与 MySQL 端口
- **THEN** 连接失败；所有 API 请求仅能通过 Nginx 暴露的入口访问

### Requirement: 界面布局与北大红视觉风格

前端 MUST 使用以北大红为主色调的统一视觉风格。知识库主页面左上角 MUST 显示当前用户的班级、姓名与身份（教师/学生），右上角 MUST 放置退出按钮；页面左侧为材料上传区域与材料列表，右侧为文件内容区域。学生身份下上传区域同样可见、可用，但其提交会得到 403 反馈。

#### Scenario: 主页面呈现规定的布局与身份信息

- **WHEN** 任意已登录用户进入知识库主页面
- **THEN** 左上角显示其班级、姓名与身份，右上角显示退出按钮，左侧为上传区域与材料列表，右侧为内容区域，整体以北大红为主色调

#### Scenario: 学生上传后看到明确的无权限提示

- **WHEN** 学生在页面上传区域选择文件并提交，服务端返回 403
- **THEN** 页面展示「学生无权限上传文件」的错误提示，材料列表不新增记录

## REMOVED Requirements

### Requirement: 语义检索必须强制限定在用户所属班级（原会话 Cookie 版本）

**Reason**: 该需求中「从服务端会话取得 class_id」和「未携带有效会话 Cookie」等表述基于 Cookie 会话认证，已被 JWT access token 认证机制取代。新的认证方式下，class_id 从 JWT token 中解析，而非服务端会话。

**Migration**: 该需求的「班级强制限定」核心行为保持不变，但认证载体从 Cookie 改为 JWT。相关场景已在本变更的 MODIFIED 章节中更新。

### Requirement: 语义检索必须强制限定在用户所属班级（检索相关场景）

**Reason**: 原需求中「未携带有效会话 Cookie 调用检索接口」等场景描述已过时。

**Migration**: 检索接口的班级过滤、空查询拒绝、伪造班级参数无效等核心行为保持不变，但认证方式统一改为 JWT access token。相关场景已在本变更的 MODIFIED 章节中更新。

### Requirement: 向量检索服务仅内部可达并参与健康检查

**Reason**: 该需求描述的是向量库基础设施约束，与认证方式无关，属于原有需求且未发生行为变化。

**Migration**: 该需求保持不变，继续适用。

### Requirement: 前端提供语义检索入口与引用展示

**Reason**: 该需求描述的是前端交互与展示行为，与认证方式无关，属于原有需求且未发生行为变化。

**Migration**: 该需求保持不变，继续适用。
