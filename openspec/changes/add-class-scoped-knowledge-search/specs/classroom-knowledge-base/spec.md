## ADDED Requirements

### Requirement: 语义检索必须强制限定在用户所属班级

系统 MUST 提供受登录会话保护的知识库语义检索能力。用户提交自然语言查询时，系统 MUST 从服务端会话（而非请求参数）取得该用户的 `class_id`，并将其作为向量相似度检索的强制过滤条件；系统 MUST NOT 读取或采信请求中任何形式的班级标识。检索命中的分片 MUST 全部来自当前用户所属班级的材料，其他班级的分片 MUST NOT 被召回，也 MUST NOT 通过分片数量、评分或错误信息泄露外班材料的存在。查询文本为空或超过长度上限时 MUST 返回 400；未登录调用 MUST 返回 401。

#### Scenario: A 班用户检索只召回 A 班材料分片

- **WHEN** A 班的学生或教师提交一个两班材料中均存在相近内容的查询
- **THEN** 返回的每条命中分片的 `class_id` 均为该 A 班用户所属班级，且不存在任何归属 B 班的分片

#### Scenario: 请求中伪造班级参数无效

- **WHEN** 用户在检索请求中附加、篡改 `class_id`、`classId` 或其他班级标识参数尝试检索外班知识
- **THEN** 系统忽略这些参数，仍仅按服务端会话中的班级过滤，越方访问不成立

#### Scenario: 未登录调用检索接口被拒绝

- **WHEN** 未携带有效会话 Cookie 调用检索接口
- **THEN** 系统返回 HTTP 401，响应体不包含任何分片或材料数据

#### Scenario: 空查询被拒绝

- **WHEN** 已登录用户提交空字符串（或仅空白字符）作为查询
- **THEN** 系统返回 HTTP 400 且不调用向量化与向量检索

### Requirement: 材料经过解析、分块与向量化索引

系统 MUST 对班级材料执行「解析 → Chunk 切分 → Embedding 向量化 → 写入向量库」的索引管线。教师通过既有上传能力新增材料成功后，系统 MUST 自动对该材料建立索引，无需任何人工触发；服务启动时 MUST 为预置种子材料以及任何处于未完成状态（从未索引或上次索引失败）的材料回填/重建索引。每份材料 MUST 具有可观测的索引状态（`pending` / `ready` / `failed`），且只有 `ready` 材料的分片可以被检索召回。索引过程失败 MUST NOT 回滚或破坏材料上传的既有成果（文件与 handouts 记录保留），失败材料 MUST NOT 被召回。

#### Scenario: 教师上传后材料自动完成索引并可被检索

- **WHEN** 教师成功上传一份包含可提取文本的 txt/md/pdf 材料
- **THEN** 材料先以 `pending` 状态出现，索引完成后转为 `ready`，随后用与其内容相关的自然语言查询可以检索到该材料的分片

#### Scenario: 全新启动后预置种子材料自动可检索

- **WHEN** 使用空数据卷全新启动系统并完成初始化
- **THEN** 两班预置讲义被自动索引为 `ready`，学生 A1 与学生 B1 分别只能检索到本班预置讲义的分片

#### Scenario: 向量化服务失败时材料保留且不被召回

- **WHEN** 索引某材料时 Embedding 服务不可用或返回错误
- **THEN** 该材料状态转为 `failed` 并记录错误原因，其文件与 handouts 记录仍然存在且可在列表中查看，检索不会命中该材料的任何分片

#### Scenario: 服务重启后未完成索引被回填

- **WHEN** 系统重启时存在 `pending` 或 `failed` 状态的材料
- **THEN** 系统在启动后自动重新索引这些材料，成功后转为 `ready`；已 `ready` 的材料不会被重复索引或产生重复分片

### Requirement: 每个分片必须携带班级归属与可定位的来源元数据

写入向量库的每个分片 MUST 携带以下元数据：`document_id`（所属材料标识）、`class_id`、稳定且全局唯一的 `chunk_id`、原始文件名、文件类型以及分片正文。此外，分片 MUST 携带按文件类型区分的来源位置：PDF 材料 MUST 记录该分片文本所在的页码；Markdown 材料 MUST 记录从各级标题推导的章节路径；TXT 材料 MUST 记录起止行号。分片的 `document_id`/`class_id` 关联 MUST 与 MySQL 中 handouts 记录保持一致。

#### Scenario: PDF 分片可定位到页码

- **WHEN** 一份 PDF 材料被索引
- **THEN** 其每个分片的来源位置包含一个正整数页码，用户可凭该页码在原 PDF 中找到分片文本

#### Scenario: Markdown 分片可定位到章节

- **WHEN** 一份 Markdown 材料被索引
- **THEN** 其每个分片的来源位置包含该文本所属的标题章节路径（如「第一章 > 集合的概念」）

#### Scenario: TXT 分片可定位到行号区间

- **WHEN** 一份 TXT 材料被索引
- **THEN** 其每个分片的来源位置包含起止行号，且该行号区间在原文件中覆盖分片正文

#### Scenario: 重建索引不产生重复分片

- **WHEN** 同一份材料因重试或回填被再次索引
- **THEN** 该材料旧分片被同一 `chunk_id` 覆盖或先删后建，向量库中该 `document_id` 的分片集合与最新切分结果一致，不出现历史残留与重复命中

### Requirement: 检索结果必须可溯源

检索接口对每条命中 MUST 返回分片正文片段与一个 Citation 来源对象。Citation MUST 至少包含：所属材料的 `document_id`、原始文件名、文件类型，以及按文件类型给出的精确位置（PDF 页码 / Markdown 章节路径 / TXT 行号区间）与相似度评分。系统 MUST NOT 返回任何缺少来源信息的命中结果；前端可凭 `document_id` 在本班材料列表中定位并打开原文。无匹配时 MUST 返回空列表的成功响应，而非错误。

#### Scenario: 每条命中包含文件名与精确位置

- **WHEN** 检索成功返回若干命中
- **THEN** 每个命中对象都同时包含分片正文、原始文件名与位置字段，且位置与分片元数据一致

#### Scenario: 可凭来源打开本班原文

- **WHEN** 用户在前端点击某条命中的引用来源
- **THEN** 系统打开 `document_id` 指向的本班材料内容预览；若该材料不属于本班则拒绝访问

#### Scenario: 无匹配返回空列表

- **WHEN** 查询在本班材料中没有任何达到召回条件的分片
- **THEN** 接口返回 HTTP 200 与空的结果数组，前端展示「本班知识库中未找到相关内容」类提示

### Requirement: 向量检索服务仅内部可达并参与健康检查

向量数据库 MUST 仅接入 Compose 内部网络，MUST NOT 向宿主机或外部网络发布端口；Go 后端 MUST 通过内部服务名访问它。`GET /health` MUST 同时反映 MySQL 与向量库的可用性：向量库不可用时 MUST 返回 5xx。向量库不可用期间的检索请求 MUST 返回 5xx 友好错误，且错误响应 MUST NOT 泄露内部服务地址或端口。

#### Scenario: 宿主机无法直连向量库

- **WHEN** 系统启动后从宿主机尝试直接连接向量库的服务端口
- **THEN** 连接失败，向量库只能由后端经内部网络访问

#### Scenario: 向量库故障时健康检查与检索失败

- **WHEN** 向量库容器停止且 MySQL 正常
- **THEN** `GET /health` 返回 5xx，检索接口返回 5xx 且不返回分片数据

#### Scenario: 向量库恢复后服务自愈

- **WHEN** 向量库从故障中恢复
- **THEN** 健康检查回到 200，检索接口重新正常返回结果

### Requirement: 前端提供语义检索入口与引用展示

知识库主页面 MUST 在不破坏既有上传、列表、预览、下载布局的前提下提供语义检索入口（输入框与提交）。检索结果 MUST 在页面内容区以分片卡片列表展示，每张卡片 MUST 包含分片正文与引用来源徽标（文件名 + 页码/章节/行号）。点击引用徽标 MUST 能打开对应材料的内容预览。教师与学生使用同一检索入口，可见范围差异完全由服务端班级边界决定。

#### Scenario: 检索结果以带引用的卡片展示

- **WHEN** 已登录用户输入问题并提交检索
- **THEN** 内容区展示若干分片卡片，每张卡片显示正文片段、原始文件名与页码/章节/行号徽标及相关度排序

#### Scenario: 点击引用打开对应材料

- **WHEN** 用户点击某张结果卡片的引用徽标
- **THEN** 右侧预览打开该 `document_id` 对应的本班材料（PDF 在对应语境下可看到页码提示）

#### Scenario: 学生在前端无法获得外班检索结果

- **WHEN** 学生 A1 与学生 B1 分别提交同一查询
- **THEN** 两人看到的分片卡片分别只来自 A 班与 B 班材料，前端不存在任何可切换班级或扩大检索范围的控件
